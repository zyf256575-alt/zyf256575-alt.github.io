# 游戏履历“最近在玩”筛选设计

## 目标

在不改变现有游戏档案结构和平台分类的前提下，完成三个点对点调整：

1. 删除控制栏右侧重复的结果数量（如“65 项”）。
2. 在现有分段筛选组中加入“最近在玩”。
3. 将《英雄联盟》标记为活跃，并让“最近在玩”在当前平台内筛选活跃游戏。

本轮先在本地预览验证，不推送线上站点。

## 已选方案

采用控制栏方案 A：

`全部 / 最近在玩 / 全成就`

“最近在玩”位于现有“全部”和“全成就”之间，保持控制栏紧凑，不增加新的工具栏或独立入口。

## 交互规则

- 默认仍进入当前平台的“全部”列表。
- 点击“最近在玩”后，只显示当前平台中的活跃游戏。
- “最近在玩”模式下，当前平台标签继续保持选中强调，明确结果所属平台。
- 点击任一平台标签时，继续保持“最近在玩”，并切换为该平台的活跃游戏列表。
- 点击“全部”或“全成就”只切换分段筛选，当前平台保持不变。
- 点击“全成就”，沿用原有 Steam 全成就语义；非 Steam 平台下仍按现有规则不可用。
- 搜索、类型筛选和排序继续作用于当前结果集，因此在“最近在玩”中仍可组合使用。

## 活跃数据规则

- Steam：`playtime2WeeksMinutes > 0` 时自动视为活跃。
- 人工档案：允许使用显式布尔字段 `active: true`。
- 《英雄联盟》增加 `active: true`。
- 当前预期活跃记录共 5 项，按平台呈现：
  - Steam：潜水员戴夫、Lies of P、Counter-Strike 2、Nioh 3
  - 腾讯 / WeGame：英雄联盟
- 仅有“至今”的游玩跨度不自动推导为活跃，避免把长期履历文字误当成近期状态。

## 展示与可访问性

- “最近在玩”沿用现有分段按钮视觉，不新增强烈装饰。
- 活跃游戏继续在详情旁显示现有的小型“活跃”状态文字。
- 删除 `#result-count` 节点、更新逻辑及对应样式；平台标签自身的数量保留。
- 分段按钮继续通过 `aria-pressed` 或当前既有等价状态表达选中状态；平台标签始终表达当前平台上下文。

## 验收标准

1. 控制栏不再出现“65 项”等结果数量。
2. 分段筛选顺序为“全部 / 最近在玩 / 全成就”。
3. Steam 下点击“最近在玩”显示 4 项 Steam 活跃游戏；腾讯 / WeGame 下显示《英雄联盟》。
4. “最近在玩”期间切换平台，分段状态保持不变，平台标签与列表同步切换。
5. 搜索、排序、类型筛选与全成就筛选没有回归。
6. 《英雄联盟》在腾讯 / WeGame 普通列表和该平台活跃列表中均显示“活跃”。
7. JavaScript 语法检查、现有测试和新增交互契约测试全部通过。

## 回滚边界

- 设计说明单独提交，生产实现另行提交。
- 本地预览验收前不推送。
- 若观感不合适，可只回滚实现提交，不影响现有线上页面和本设计记录。
