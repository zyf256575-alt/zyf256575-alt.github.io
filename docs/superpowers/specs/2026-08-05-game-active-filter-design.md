# 游戏履历“最近在玩”筛选设计

## 目标

在不改变现有游戏档案结构和平台分类的前提下，完成三个点对点调整：

1. 删除控制栏右侧重复的结果数量（如“65 项”）。
2. 在现有分段筛选组中加入“最近在玩”。
3. 将《英雄联盟》标记为活跃，并让“最近在玩”跨平台汇总活跃游戏。

本轮先在本地预览验证，不推送线上站点。

## 已选方案

采用控制栏方案 B：

`全部 / 最近在玩 / 全成就`

“最近在玩”位于现有“全部”和“全成就”之间，保持控制栏紧凑，不增加新的工具栏或独立入口。

## 交互规则

- 默认仍进入当前平台的“全部”列表。
- 点击“最近在玩”后，结果临时切换为跨平台汇总，不受当前平台标签限制。
- 跨平台模式下，平台标签取消选中强调，避免让用户误以为结果仍受某个平台限制。
- 点击任一平台标签，退出“最近在玩”，回到该平台的“全部”列表。
- 点击“全部”，退出“最近在玩”，恢复进入该模式前的平台。
- 点击“全成就”，沿用原有 Steam 全成就语义；非 Steam 平台下仍按现有规则不可用。
- 搜索、类型筛选和排序继续作用于当前结果集，因此在“最近在玩”中仍可组合使用。

## 活跃数据规则

- Steam：`playtime2WeeksMinutes > 0` 时自动视为活跃。
- 人工档案：允许使用显式布尔字段 `active: true`。
- 《英雄联盟》增加 `active: true`。
- 当前预期跨平台活跃列表共 5 项：
  - 潜水员戴夫
  - Lies of P
  - Counter-Strike 2
  - Nioh 3
  - 英雄联盟
- 仅有“至今”的游玩跨度不自动推导为活跃，避免把长期履历文字误当成近期状态。

## 展示与可访问性

- “最近在玩”沿用现有分段按钮视觉，不新增强烈装饰。
- 活跃游戏继续在详情旁显示现有的小型“活跃”状态文字。
- 删除 `#result-count` 节点、更新逻辑及对应样式；平台标签自身的数量保留。
- 分段按钮继续通过 `aria-pressed` 或当前既有等价状态表达选中状态；跨平台模式应让平台标签不再呈现选中态。

## 验收标准

1. 控制栏不再出现“65 项”等结果数量。
2. 分段筛选顺序为“全部 / 最近在玩 / 全成就”。
3. 点击“最近在玩”能同时看到 4 项 Steam 活跃游戏和《英雄联盟》。
4. 点击任一平台后恢复该平台全部列表。
5. 搜索、排序、类型筛选与全成就筛选没有回归。
6. 《英雄联盟》在普通平台列表和跨平台活跃列表中均显示“活跃”。
7. JavaScript 语法检查、现有测试和新增交互契约测试全部通过。

## 回滚边界

- 设计说明单独提交，生产实现另行提交。
- 本地预览验收前不推送。
- 若观感不合适，可只回滚实现提交，不影响现有线上页面和本设计记录。
