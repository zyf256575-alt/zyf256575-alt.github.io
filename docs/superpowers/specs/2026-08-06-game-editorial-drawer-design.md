# 游戏履历详情抽屉设计

## 目标

针对带有个人游玩记录或游戏截图的条目，替换当前在列表行内展开的详情面板：

1. 展开详情时不再撑高当前游戏行，也不推动后续游戏。
2. 采用用户确认的方案 A：保留桌面端右侧抽屉，但将主体改为“通栏大图 + 单栏叙事”的杂志式上下结构。
3. 截图只展示画面，不显示逐张说明文字；保留替代文本与可访问名称。
4. 将《魔兽争霸 III》封面换成具有经典《冰封王座》辨识度的高清素材。
5. 点击主图时不再跳到裸图片网页，而是在当前页面查看原图并连续翻页。

用户在抽屉初版验收后追加三项范围：《戴森球计划》的个人记录改为用户确认的一句短注脚；截图采用缩略图、抽屉预览图、Steam 原始 JPG 三档资源；点击抽屉主图后在页内原图查看器中翻页。本轮仍不扩展其他游戏的个人评价。

## 已选视觉方案

采用右侧抽屉的“杂志封面式”上下布局：

- 游戏列表留在背景中，覆盖一层低强度暗幕。
- 抽屉从视口右侧进入，桌面端宽度约为 `min(900px, 62vw)`，高度占满视口。
- 顶部为固定标题区：游戏名、游玩跨度、时长和现有类型标签；右上角为关闭按钮。
- 标题区下方先展示通栏截图画廊。桌面端主图占满约 `836px` 的内容宽度，保持 `16:9`，不再被双栏压缩到约 `430px`。
- 四张缩略图紧接主图横向排列，仍负责切换主图；主图继续作为打开原图查看器的入口。
- 个人游玩记录放在画廊下方，以 `680px` 的最大阅读宽度居中排版；内容允许只保留一句短注脚，不新增成就卡片、统计仪表盘或额外总结。
- 主图、缩略图和正文共同参与抽屉内部的自然滚动；不再让画廊吸附在右侧，避免正文结束后留下大块无意义空白。
- 不显示“游戏内截图”标题和每张图片下方的说明文字，避免像资料汇编。
- 保留青绿色强调、细边框、黑灰底和紧凑等宽小标签，延续游戏履历现有工业化视觉语言。

- 取消占据图片宽度的左右导航列；上一张、下一张按钮绝对定位覆盖在画面左右边缘，关闭按钮仍位于右上角，计数仍位于底部中央。

## 交互结构

### 带个人内容的游戏

- 列表中的“详情”改为按钮，并通过 `aria-haspopup="dialog"` 指向抽屉。
- 点击后打开一个全局复用的模态抽屉，而不是把内容插入当前 `.game-row`。
- 抽屉内容根据所点游戏动态填充；列表行本身尺寸保持不变。
- 点击缩略图切换主图；当前缩略图提供可见状态和 `aria-current`。
- 抽屉主图读取 `screenshots[].src` 作为轻量预览，缩略图优先读取 `screenshots[].thumbSrc`，缺失时回退到 `src`。
- 主图使用按钮语义；点击后打开页内原图查看器，不创建新标签页。
- 关闭方式包括右上角按钮、`Escape` 和点击抽屉外暗幕。
- 关闭后焦点返回原来的“详情”按钮。
- 抽屉打开期间锁定页面背景滚动；抽屉内部独立滚动。

### 原图查看器

- 使用第二个全局复用的模态 `dialog` 覆盖在详情抽屉之上。
- 只在查看器打开或切换图片时，把当前图片的 `fullSrc` 赋给大图；没有 `fullSrc` 时回退到 `src`，不预加载相邻原图。
- 左右按钮、键盘 `ArrowLeft` / `ArrowRight` 均可循环切换；顶部关闭按钮、`Escape` 和点击暗幕关闭查看器。
- 显示 `01 / 04` 计数，不显示图片说明文字；关闭后焦点返回抽屉主图按钮。

### 只有基础资料的游戏

- 没有 `review` 和 `screenshots` 的条目继续使用现有轻量行内详情。
- 不因为这次改造给尚无个人内容的游戏生成空抽屉。

## 响应式规则

- 桌面端：画廊通栏置顶，正文在其下方单栏居中；主图使用抽屉内容区的完整可用宽度。
- 中等宽度：抽屉扩大到视口的大部分宽度，继续保持相同的上下顺序，不切换回双栏。
- 手机端：抽屉变成全屏页面层；画廊与正文保持上下结构，缩略图允许四等分收窄，关闭按钮保持在顶部可见。
- 原图查看器始终占满视口，原图采用 `object-fit: contain`；窄屏时上一张、下一张按钮贴近底部，避免遮挡画面中心。
- 所有尺寸下均不得让底层列表发生布局位移。

## 数据边界

- 继续沿用 `review` 数组和 `screenshots` 数组，不建立第二套详情数据。`src` 是抽屉预览图，`thumbSrc` 是可选的 320×180 WebP，`fullSrc` 是可选的 Steam 原始 JPG。
- `screenshots[].alt` 继续用于图片替代文本。
- 现有 `screenshots[].caption` 可保留为内部语义或原图链接名称，但前台不渲染 `figcaption`。
- 《戴森球计划》的 `review` 只保留用户确认的一句短注脚，不从旧长文补写信息；四张截图画面不变，每张保留预览 WebP、320×180 缩略图与对应 Steam 原始 JPG。

## 《魔兽争霸 III》封面

- 使用高清、完整、具有经典《魔兽争霸 III：冰封王座》辨识度的官方风格素材，核心视觉应包含经典角色对照或《冰封王座》标识。
- 优先下载真实经典素材并本地化，不依赖外链；仅在找不到合适素材时才考虑生成。
- 按列表横向封面比例做有意识的裁切或横幅适配，避免把竖版盒图直接拉伸，也不能裁掉主要面孔和标题标识。
- 输出使用仓库内 PNG 资产 `manual-warcraft3.png`，不依赖外链。

## 可访问性与降级

- 抽屉使用原生 `dialog` 或等价的模态语义，并设置可读标题关联。
- 支持键盘打开、缩略图切换和关闭；焦点不会落到背景列表。
- 浏览器不支持动画或用户启用 `prefers-reduced-motion` 时，抽屉直接出现，不强制位移动画。
- 图片加载失败时沿用现有封面或截图占位逻辑，正文仍可阅读。

## 验收标准

1. 打开《戴森球计划》详情时，任何游戏行的高度和位置都不变化。
2. 桌面端抽屉从右侧覆盖，通栏主图与四张缩略图位于个人注脚上方；主图宽度接近抽屉内容区全宽，注脚保持单栏宽度。
3. 前台不出现逐张截图说明文字。
4. 关闭按钮、`Escape`、点击暗幕均可关闭，且焦点返回触发按钮。
5. 手机端为单栏全屏详情，不产生横向滚动。
6. 没有个人记录的游戏仍保持现有轻量详情行为。
7. 《魔兽争霸 III》列表封面呈现经典《冰封王座》视觉，不再使用当前重制版金发角色横图。
8. JavaScript 语法检查、现有游戏档案测试和新增抽屉交互契约测试全部通过。
9. 抽屉首次打开只加载 WebP 预览与缩略图；点击主图后才加载当前 2560×1440 JPG。
10. 原图查看器可通过按钮和方向键循环翻完四张图片，关闭后不离开游戏履历页面。
11. 桌面端原图查看器中的图片不再因固定导航列和大幅左右内边距缩小，视觉尺寸接近 Steam 大图查看页。
12. 全成就游戏封面呈现克制的渐变边框，普通游戏封面尺寸和样式不变。

## 2026-08-09 追加：连续浏览式作品档案（方案 A）

用户在两套同内容原型中选择方案 A。该方案取代此前的右侧模态抽屉，目标是让游戏履历始终保持“可连续浏览的档案列表”，而不是每次打开详情都离开列表或让当前行大幅增高。本文前半部分的抽屉结构与抽屉验收项仅保留为历史方案记录；自本节起，若与旧抽屉方案冲突，以本节为准。

### 页面结构

- 桌面端采用稳定的左右工作区：左侧保留紧凑游戏列表，右侧为当前选中游戏的作品档案；切换游戏只更新右侧内容，左侧列表不重排、不被遮罩、不锁定滚动。
- 右侧作品档案按两层信息组织：上层为“作品内容”，下层为“个人记录”。两层之间用标题、分隔线和文案口径明确区分资料性描述与用户观点。
- “作品内容”以横向封面轨道呈现游戏本体、资料片和 DLC。每个内容项是结构化实体，至少包含 `type`、`title`、`cover` 和 `description`；点击封面后只替换对应的资料性描述。
- “个人记录”继续呈现用户短评、周目、个人荣誉、全成就、游玩跨度和截图。个人短评不得与本体或 DLC 的自动描述合并成同一段，也不由自动文案冒充用户观点。
- 没有资料片或 DLC 的游戏只显示本体封面与本体描述，不生成空卡位；没有个人短评或截图的游戏不生成空模块。

### 交互规则

- 点击列表行或“游玩记录”入口后，将该游戏设为当前选中项，并在右侧更新作品档案；当前行通过细强调线或弱底色标识，不改变行高。
- 点击本体、资料片或 DLC 封面，只切换右侧的当前内容说明，不改变个人短评、标签与截图。
- 截图仍使用页内原图灯箱；关闭灯箱后焦点返回触发缩略图，不退出作品档案。
- 窄屏不强行维持双栏：列表与作品档案纵向排列，选择游戏后将档案滚动到可见区域；不恢复旧的模态抽屉。
- 右侧没有选中游戏时显示克制的空状态，引导用户从列表选择；页面初次加载默认选中当前排序下的第一款游戏。

### 数据边界

- 本次实现先完成连续浏览交互与作品内容的数据接口，不在同一轮批量生成全部游戏文案。
- 现有 `review`、`playthroughs`、`honors`、`screenshots` 等字段继续作为个人记录真源。
- 新增的作品内容集合应与个人记录分离；本体、资料片和 DLC 不再只作为 `reviewSections` 中的标题文本存在。
- 迁移时允许先为已有人工作品分段的游戏建立结构化内容，其余游戏回退为单一本体项；不得用占位文案污染正式页面。

- 只修改 Game Log 页面结构、样式、必要的数据适配器和自动化测试。
- 保留现有排序、平台筛选、活跃筛选、成就统计、封面渐变边框、原图灯箱与已确认个人短评。

2. 本体、资料片和 DLC 以封面轨道呈现，切换内容时资料描述更新，个人短评与个人标签不变。
