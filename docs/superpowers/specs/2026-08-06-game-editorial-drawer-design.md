# 游戏履历长篇详情抽屉设计

## 目标

针对带有个人游玩记录或游戏截图的条目，替换当前在列表行内展开的详情面板：

1. 展开详情时不再撑高当前游戏行，也不推动后续游戏。
2. 采用用户确认的方案 A：桌面端右侧抽屉，正文与截图图文并排。
3. 截图只展示画面，不显示逐张说明文字；保留替代文本与可访问名称。
4. 将《魔兽争霸 III》封面换成具有经典《冰封王座》辨识度的高清素材。

本轮只调整详情交互与《魔兽争霸 III》封面，不改写已确认的《戴森球计划》正文，也不扩展其他游戏的个人评价。

## 已选视觉方案

采用右侧抽屉的“图文并排”布局：

- 游戏列表留在背景中，覆盖一层低强度暗幕。
- 抽屉从视口右侧进入，桌面端宽度约为 `min(900px, 62vw)`，高度占满视口。
- 顶部为固定标题区：游戏名、游玩跨度、时长和现有类型标签；右上角为关闭按钮。
- 主体左侧为个人游玩记录，控制在适合阅读的行宽内。
- 主体右侧为截图画廊：一张主图加三张缩略图；画廊可在长文滚动时保持可见。
- 不显示“游戏内截图”标题和每张图片下方的说明文字，避免像资料汇编。
- 保留青绿色强调、细边框、黑灰底和紧凑等宽小标签，延续游戏履历现有工业化视觉语言。

## 交互结构

### 带长篇内容的游戏

- 列表中的“详情”改为按钮，并通过 `aria-haspopup="dialog"` 指向抽屉。
- 点击后打开一个全局复用的模态抽屉，而不是把内容插入当前 `.game-row`。
- 抽屉内容根据所点游戏动态填充；列表行本身尺寸保持不变。
- 点击缩略图切换主图；当前缩略图提供可见状态和 `aria-current`。
- 点击主图可打开本地原图。
- 关闭方式包括右上角按钮、`Escape` 和点击抽屉外暗幕。
- 关闭后焦点返回原来的“详情”按钮。
- 抽屉打开期间锁定页面背景滚动；抽屉内部独立滚动。

### 只有基础资料的游戏

- 没有 `review` 和 `screenshots` 的条目继续使用现有轻量行内详情。
- 不因为这次改造给尚无个人内容的游戏生成空抽屉。

## 响应式规则

- 桌面端：正文与画廊双栏，画廊在右侧。
- 中等宽度：抽屉扩大到视口的大部分宽度，双栏比例收紧。
- 手机端：抽屉变成全屏页面层，正文与画廊改为单栏；关闭按钮保持在顶部可见。
- 所有尺寸下均不得让底层列表发生布局位移。

## 数据边界

- 继续沿用 `review` 数组和 `screenshots` 数组，不建立第二套详情数据。
- `screenshots[].alt` 继续用于图片替代文本。
- 现有 `screenshots[].caption` 可保留为内部语义或原图链接名称，但前台不渲染 `figcaption`。
- 《戴森球计划》的三段正文和四张截图内容不变。

## 《魔兽争霸 III》封面

- 使用高清、完整、具有经典《魔兽争霸 III：冰封王座》辨识度的官方风格素材，核心视觉应包含经典角色对照或《冰封王座》标识。
- 优先下载真实经典素材并本地化，不依赖外链；仅在找不到合适素材时才考虑生成。
- 按列表横向封面比例做有意识的裁切或横幅适配，避免把竖版盒图直接拉伸，也不能裁掉主要面孔和标题标识。
- 输出仍使用仓库内 WebP 资产，并复用现有 `manual-warcraft3.webp` 路径，便于回滚和避免数据层改名。

## 可访问性与降级

- 抽屉使用原生 `dialog` 或等价的模态语义，并设置可读标题关联。
- 支持键盘打开、缩略图切换和关闭；焦点不会落到背景列表。
- 浏览器不支持动画或用户启用 `prefers-reduced-motion` 时，抽屉直接出现，不强制位移动画。
- 图片加载失败时沿用现有封面或截图占位逻辑，正文仍可阅读。

## 验收标准

1. 打开《戴森球计划》详情时，任何游戏行的高度和位置都不变化。
2. 桌面端抽屉从右侧覆盖，正文在左、截图在右，主图和三张缩略图完整可用。
3. 前台不出现逐张截图说明文字。
4. 关闭按钮、`Escape`、点击暗幕均可关闭，且焦点返回触发按钮。
5. 手机端为单栏全屏详情，不产生横向滚动。
6. 没有个人记录的游戏仍保持现有轻量详情行为。
7. 《魔兽争霸 III》列表封面呈现经典《冰封王座》视觉，不再使用当前重制版金发角色横图。
8. JavaScript 语法检查、现有游戏档案测试和新增抽屉交互契约测试全部通过。

## 回滚边界

- 本设计说明单独提交，生产实现另行提交。
- 本轮不推送远端；用户本地预览确认后再决定是否提交和推送实现。
- 若抽屉观感不合适，可单独回滚实现提交，恢复现有行内详情，不影响游戏数据和已确认正文。
