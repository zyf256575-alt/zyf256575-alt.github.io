# 游戏履历个人荣誉章设计

## 目标

在展开的“游玩记录”中，为极少数具有明确个人地位的游戏显示主观荣誉章。它用于快速表达个人判断，不替代类型标签、全成就状态或短评，也不要求每款游戏都有。

首批仅包含：

- 《艾尔登法环》：`GOAT`
- 《巫师 3：狂猎》：`剧情 GOAT`

## 已选方案

采用方案 A：在详情内容右侧建立纵向徽章栏。已有周目徽章排在上方，个人荣誉章紧随其下。

- 《艾尔登法环》依次显示 `5 周目`、`GOAT`。
- 《巫师 3：狂猎》依次显示 `2 周目`、`剧情 GOAT`。
- 徽章只在展开“游玩记录”后出现，不进入折叠状态下的主列表元数据行。
- 没有周目但拥有个人荣誉的游戏，荣誉章仍占用同一右侧徽章栏的首位，不生成空占位。

## 数据结构

在单个游戏记录上增加可选字符串数组 `personalHonors`。仅非空字符串参与渲染；没有该字段或数组为空时不创建荣誉章容器。

该字段是选择性的个人判断层。本轮不从短评自动推导，不批量生成，也不改写现有 `review`、`playthroughs`、类型或成就字段。

## 视觉规则

- 周目徽章保留现有紫色样式。
- 个人荣誉章使用克制的青色到暖金色细渐变边框、深色内底和浅色文字，避免强外发光。
- 两类徽章统一尺寸、圆角与字级，纵向间距保持紧凑；荣誉章可以因文字长度自然变宽。
- 右侧徽章栏不得挤压短评正文或截图区域。窄屏时移动到详情内容下方并左对齐。
- `全成就` 仍是客观完成状态，继续位于原有列表状态区，不与个人荣誉章合并。

## 交互与可访问性

- 荣誉章不是按钮，不增加点击行为或悬浮说明。
- 每枚荣誉章提供 `aria-label="个人荣誉：<内容>"`。
- 详情折叠时不显示，也不在无荣誉数据的条目中保留空白。

## 验收标准

1. 《艾尔登法环》展开后，右侧依次显示 `5 周目` 与 `GOAT`。
2. 《巫师 3：狂猎》展开后，右侧依次显示 `2 周目` 与 `剧情 GOAT`。
3. 两枚个人荣誉章不出现在折叠列表元数据行。
4. 其他游戏不新增推测性标签，也不出现空徽章栏。
5. 桌面与窄屏布局均不挤压短评和截图；现有全成就、周目、灯箱和筛选测试继续通过。
